# Spec 007：官网文案接上三层真源

> 造什么与为什么，不碰技术实现。
> 状态：已落地｜创建：2026-10-02｜上游：hachimi-ios spec 113 与 ADR-0060｜上一版：[006](../006-one-page/spec.md)

## 为什么

owner 2026-10-02 北京时间 14:06：所有文案思路参考梁宁《真需求》《产品思维 30 讲》《增长思维 30 讲》充分调整，整体上管好真源，把理念、规约与最终文案做好顶层设计。

顶层设计落在 hachimi-ios：产品论纲讲理念，文案原则讲写法与各面的职责，定稿句表收两个面以上共用的句子，由门逐字核对落点。官网是其中一个面。照论纲对照 006 的首页，问题有四个：口号讲慌时起卦，下面直接讲排盘，中间缺一座桥；没有一句让人记住的话，定位句同时承担称呼与记忆点；“换了手机，命例都在”是必备属性，占着三件之一；常见问题缺了“能不能和我现在用的盘对上”和“会员管什么”这两个装之前最想问的。

## 站位

同 006：读者第一位是给人看盘的命理师与命理爱好者，拿首页判断要不要装；第二位是慌了想起一卦的访客，与从商店跳回来确认的人。说话的是产品方，讲工具能做什么。网页扫读，中英双语，按应用商店与公众这一头定口吻。

## 造什么

### 定稿句

官网用到定稿句表里的五句，逐字照表：C1 口号、C2 过桥、C3 称呼、C4 记忆锤、C6 资料不在会员里。表在 hachimi-ios `docs/copy-canon.md`，官网不另存一份。

### 各节

- 首屏：口号下一行是过桥句 C2。
- 定位（`#what`）：先点称呼 C3，大字换成记忆锤 C4。三件依次是录一次两张盘、点开这一位盘和卦都在、紫微三种盘式与八字六柱。“换了手机”从三件里撤下，进常见问题。
- 命例走查（`#case`）：从“有人报来一个生辰”起笔，引言把客户、家人、朋友与自己写在一起。
- 四件工具：卡面与展开去重，同一件事只在一处说。
- 常见问题六条依次是：真太阳时、能和我现在用的盘对上吗、要联网吗、换了手机命例还在吗、刚开始学用得上吗、会员管什么。会员一条的答案里有 C6。
- 站点描述、`site.webmanifest` 与 `llms.txt` 跟着用称呼与记忆锤。

### 验收标准

1. GIVEN 官网仓，WHEN 跑 `npm run check`，THEN 其中 `check:canon` 调 hachimi-ios 的定稿句门只核官网一段，五句逐字对上；兄弟仓不在旁边时报错，不放过。
2. GIVEN `/zh` 与 `/en` 首屏，THEN 口号下一行是过桥句；定位一节先是称呼行，大字是记忆锤。
3. GIVEN 字数门，THEN 全绿，过桥句单列一档上限。
4. GIVEN 浏览器实拍桌面 1440 与手机 390、中英、浅深，THEN 过桥句与记忆锤不在词中间断行，无横向溢出。
5. 推 main 上线后回读线上首屏与 `llms.txt`。

### 不做

- 首屏口号不改，owner 定的。
- 页脚“中国民俗术数的学习与研究工具”不改，那是类目说明。
- 节结构、节序与各节视觉不动。
